## 1. 사용자 상황
- 카메라: Canon EOS 6D Mark II. 렌즈: EF 24-105mm f/4L IS USM(I형/II형 미확인) + EF 50mm f/1.8 STM.
- 촬영 목적: 아이(5세 전후) + 인물. 오토로 찍으면 폰보다 못 나와서 수동 세팅을 배우고 싶음.
- 호주 가족여행 12/29~1/18. 여행 전까지 폰에서 쓸 수 있으면 됨.
- 개발 도구: 클로드 코드. 사용자는 비개발자. 프롬프트는 한글, 카메라 용어는 영어 병기.
- 요청 방식: "혼자 할 수 있는 건 먼저 다 해라", "결론 나기 전엔 프롬프트 쓰지 마라", "복사할 내용은 코드블록 하나로", "프롬프트는 보내기 전 3회 검수".

## 2. 앱 개요 (현재)
- 단일 페이지 웹앱(index.html + css/style.css + js/*). 빌드·외부 라이브러리·웹폰트 금지(오프라인). 한국어, 모바일 한 손. 토스 스타일.
- 홈 탭 3개: **상황으로**(8상황 × 2피사체 → Av 세팅 + 다이얼 순서) / **원하는 사진**(스타일 9) / **사진으로**('이 사진처럼 찍기' AI 매칭 + '내 사진 진단' 오프라인 EXIF·픽셀 진단).
- 바디 10종(CAMERAS): 6D2, 5D4, R6 II, R50, R8, 90D, 80D, 6D, 200D II(250D), 850D. family(다이얼 문구 템플릿): ff2dial / crop2dial / crop1dial / rf / rf1dial / rf2dial. 렌즈 12종: EF 8 + RF 4. 조리개는 lens.portraitAp + scene.apRule.
- C 모드 없는 바디(R50·850D·200D II)는 설정에 안내 카드, 최소 셔터 메뉴 없는 바디는 움직이는 아이를 M + ISO AUTO로. 6D는 최소 셔터 상한 1/250(minShutterCap).
- 배포: claude.ai 아티팩트(폰용 링크, CLAUDE.md 참고) + 안드로이드(Capacitor). 아티팩트는 js 10개 + img 9장 전부 올려야 함.

## 3. 파일 구조와 원칙
CLAUDE.md '파일' 절과 '깨지 말아야 할 원칙' 1~12 참고. 요지:
- facts.md = 모든 숫자의 유일한 근거. 바디 추가는 매뉴얼(PDF 쪽수 또는 온라인 가이드 URL) → facts.md 절 + json → data.js → `node check.js` 통과 → 설정·결과 스크린샷.
- AI('이 사진처럼')는 분류값만, 숫자는 compute()만, 노출보정은 현재 상황에서만. 진단('내 사진 진단')은 AI 미사용·오프라인, 임계값은 test-diag.html 근거 없이 안 바꿈.
- 결과 화면 순서: 숫자 → 다이얼 순서 → 현장 조정 → 팁 → 왜. '이 세팅으로 찍기' 버튼은 두지 않음(override 손실).
- 검증 도구: `node check.js`(데이터·계산·문구·토큰·링크 이름), test.html(매칭 9장, gemini 비교), test-diag.html(진단 36장 + 가짜 EXIF 7 + 실사진 img/real/1~9.jpg), 스크래치패드 cdp-run.js(실제 앱 전체 주행, problems 0 기준) — CLAUDE.md 원칙 14.
- 2026-10-09 완성도 라운드: 버그 18건·데이터 교정(5D4 p.187, R6 II/R8/6D 화질 다이얼, 눈 검출 Auto)·UX/접근성(대비·터치 44·용어 '카메라 준비'/'등록'·공유·백업/복원·PWA) 반영. 상세는 docs/audit.md 9절. 사용자 정책 제안 P1~P11(audit.md 8절)은 여전히 승인 대기.
- 스크린샷은 헤드리스 Chrome을 DevTools 프로토콜로 제어(가상 시간 모드는 createImageBitmap을 못 기다림). 로컬 서버 필요(python -m http.server).

## 4. 완료된 작업 (시간순)
A~F 데이터 검수·토스 디자인·C1/C2·설정 페이지 → G 렌즈 8종·portraitAp/apRule·다중 렌즈 체크·가로 스크롤 칩·recommend(한 번 유실됐다가 L1에서 재수행) → H CAMERAS 배열·family 템플릿·카메라 선택·RF 렌즈 → 5D4·R6 II → I-a/I-b/I-c '이 사진처럼 찍기'(exif·analyze·match·화면·Gemini 실제 연결) → J-a/J-b '내 사진 진단'(pixels·diagnose·화면) → K 전체 점검(docs/audit.md) → L1~L11 수정 → R50·R8·90D·80D·6D·200D II·850D 추가(계획 10종 완료).

## 6. 결정 사항·하지 않기로 한 것
- CCAPI(폰→카메라 설정 전송) 안 함(6D2 미지원). 카메라 펌웨어 개조 안 함. 광고 안 함.
- Av 기본, M은 야경·실루엣만. 플래시는 다루지 않음. 하이라이트 톤 우선 권하지 않음.
- 바디 추가는 한 세션에 하나(사용자가 "혼자 다 해"라고 하면 예외).
- 당장 실전 세팅: 쩜팔이 + Av f/2.2~2.8 + ISO 자동 + 노출보정 +0.3.

## 7. 검수에서 찾았던 오류 유형 (재발 방지)
- HTP 켜면 최저 ISO 200 → 맑음 f/4가 1/4000 초과 (삭제함)
- M 모드에 노출보정 표시 (ISO 수동이면 의미 없음)
- 기본 조합에 tooDark 플래그 출고
- "ISO 한 단계 올리기. 12800 넘기면 노이즈" → 12800이 목표값처럼 읽힘
- adjust 두 규칙이 한 문장에 붙어 splitRule이 못 가름
- tips 데이터가 화면에 안 나옴
- 상황별 WB 프리셋이 C 모드에 저장 안 되는데 바꾸는 법 없음
- 레퍼런스 사진 역광 → 노출보정 +1 (상황이 아니라 스타일에 EC를 준 오류)
- G 작업이 커밋 안 된 채 다른 폴더에서 이어져 저장소에서 유실 → 작업 끝엔 반드시 커밋·푸시
- 50mm 전용 문구('f/4로 조이기')가 렌즈 무관하게 노출 → {apStop}·{maxShutter} 치환으로 일반화
- 핸드헬드 여유가 exposure.js(×4 고정)·diagnose.js(2^(isStops−2))·facts.md에서 서로 달랐음 → 통일
- 6D처럼 옛 기종은 메뉴 자체가 없는 항목(AWB 우선·안티플리커·최소 셔터 1/500)이 있음 → menu na + value/why 덮어쓰기, minShutterCap
